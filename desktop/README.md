# Sub2Ops for macOS / Android

Rust / Tauri 2 / React 运维客户端，支持 macOS 12+ 的 Apple Silicon 和 Android 12+ 的 ARM64。

## 安装与连接

从本仓库 Releases 下载对应的 `.dmg` 或 `_arm64-v8a.apk`，校验 `SHA256SUMS`。Mac 将 Sub2Ops 拖入 Applications；Android 安装签名 APK。Mac 使用本机签名，未经 Apple 公证；Android 使用固定发布签名支持覆盖升级。Mac 检查更新打开对应 DMG，Android 打开本仓库发布页，不自动安装。

填写你部署的 Companion 地址（例如 `https://companion.example.com/sub2ops`）和已有的 **Sub2API 管理员 API Key**。Mac Key 存储在 Keychain（服务 `com.lich13.sub2ops`）；Android 使用 Keystore 的不可导出 AES-GCM 密钥加密后保存在应用私有、禁止备份的目录。偏好设置及前端持久化不含 Key。断开连接删除对应凭据。

- 账号：分组、平台、类型、状态筛选；用量栏对齐 Sub2API，包含窗口请求数、Token、A/U 费用。OpenAI OAuth 显示适用的 5h/7d；Grok 付费显示 7d/30d 和预付余额，免费显示 24h；API Key 显示今日统计及已配置的日/周/总配额。调度开关只改变允许调度，不清除限流、冷却或认证错误。
- 记录：北京时间日期筛选及用户实扣总消费，展示历史真实模型路由、Token、费用和延迟。用户、账户、API 密钥可搜索筛选，隐藏已删除候选但保留停用项；历史记录和消费统计不因实体删除而移除。总消费显示六位小数。
- 分组：Mac 独立页面、Android 账号页入口；Codex / Grok 以相交区域展示独有和共有账号。仅通过拖放移组，移动端长按拖柄，统一应用草稿；范围外分组不变，保存冲突保留修改；账号行提供调度开关。
- 优先级：当前连接全部未删除账号按实际平台分别排序，每个平台从 `1..N` 编号。宽屏最多三栏，窄屏使用平台标签；各平台独立草稿、撤销和应用，只有所选平台的变化项写入。搜索仅供查看，不可编辑账号需要改值时阻止该平台应用；忙碌账号不阻塞其他未派发项，最终回读全部一致才完成。账号行提供独立调度开关；执行状态简短显示，结束结果 3 秒消失，需处理时保留重新核对入口。详见[优先级排序任务](../docs/account-operations.md#按平台优先级排序)。
- 事件：降智错误、其他错误、恢复历史和日志四个标签独立分页；保留真实历史、未关联及删除实体的错误，排除有明确证据的本地限流。日志展示已创建的自动检测终态结果，详情区分模型验证、取消标记、恢复调度和通知状态。浏览日志不会触发检测或推送。
- 功能：配置 OAuth 恢复、自动用卡、每日测活及分组模型。恢复账号可选择测试连接或一组模型验证，未选入的账号不自动恢复或用卡。
- 账号模板：从账号页管理全部模板，编辑白名单与映射，按账号预览并手动应用。标记或自动检测不改写模型配置，空模板表示不限制模型。
- 设置：Bark、连接、版本检查；开机启动仅在 Mac 显示。

Mac 主窗口默认 1310×860，按屏幕可用区居中收缩，八列账号表完整显示；再次打开不重置本次手动调整。Android 使用五项底部导航、紧凑账号块、筛选与操作弹层；快捷面板与“分组动态”按当前成员最近调用排序，每组显示最近三个不同账号。详情、测试使用全屏面板，系统返回先关闭当前面板，再返回账号页或后台。

左键菜单栏图标显示并聚焦快捷面板，分组按最近调用排序；重复点击不会关闭。图钉控制失焦后是否关闭，Escape 或关闭按钮也可关闭。右键打开主窗口、检查更新或退出。主窗口打开或最小化时显示 Dock 图标，关闭后隐藏并继续驻留菜单栏；快捷面板不影响 Dock，开机启动默认关闭；启用后登录时静默驻留菜单栏，手动打开仍显示主窗口。

快捷面板宽 420px，高度随内容收缩、最大 520px；每组展示最近调用的三个不同有效账号、调度开关、最近调用和上次错误时间，以及 OAuth 微型用量条。工具栏合并为一行，账号行高 48px，超出内容滚动。全界面时间为北京时间 `MM-DD HH:mm:ss`。用量栏保留适用的查询、次数、重置、探测，排除点数与邀请。重置消耗次数、Grok 探测可能发送模型请求，均需确认；操作串行、失败不自动重放。

账号页支持当前筛选全选、单个及批量删除和恢复状态。删除确认时列出名称、编号及数量。最多并发三个账号，逐项显示结果，失败项保留选择。恢复状态按钮只对错误、有效限流、过载、冷却或模型级限流显示，直接调用 Sub2API 的恢复状态接口，不额外查询额度或执行模型测试。

桌面账号表的操作区完整展开适用按钮，随可用宽度自动分列、换行；账号名称列仍可收起，分组及安卓保留菜单。批量操作栏提供“测试连接”“恢复状态”“选择代理”“应用模板”“删除所选”。恢复状态只提交所选的可恢复账号，按项汇报恢复、无需恢复、失败和待核对；不附加开启调度、测试或用卡。批量代理支持统一设置或清除，先逐项预览，再进入持久化队列；继承账号不可独立修改，其他账号的失败或忙碌不阻塞已具备条件的任务。代理写入只修改对应字段，结果不确定时先核对实际状态。

账号页优先级显示为只读数字，仍可按其升降序排列；数值越小优先级越高。并发及负载因子继续原位编辑，修改优先级使用独立优先级页。连接测试支持 OpenAI 普通、Compact、图像及 Grok 文本、图像、视频、搜索、TTS、STT、Realtime；弹窗内点击开始直接执行，取消不重放。流式文本保留空格、换行和缩进。测试媒体和正文只保留在当前窗口。全部额度刷新覆盖暂停在内的 OpenAI/Grok OAuth，Grok 仅刷新账单，显示逐账号进度及失败结果，批次结束停止进度轮询。

账号多选测试在整批结束 3 秒后自动收起结果，保留“测活结果”入口；手动重开不再自动关闭。运行中、提交或查询未确认时不会启动完成计时。

Mac 可见时每 2 秒读取状态，驻留后台每 15 秒。Android 前台每 2 秒合并刷新，后台停止读取和进度轮询，取消未完成的只读请求与测试流，返回前台立即刷新；云端批次及自动化继续运行。离线保留最后快照并禁用写操作，已发出的写操作不重放。刷新不调用额度查询或模型测活。

账号质量评分及其筛选、排序、详情已移除；首次按最近调用倒序，无调用账号置底。本机统一记住最后一次排序的字段和方向，重启和切换连接后沿用；桌面、移动端下拉和“调度参数”表头共用排序选择。筛选条件不保存，排序不跨设备同步。代理质量检测、慢首字检测线索和降智标记继续保留。

桌面记录表列宽进一步收窄，长账号、密钥和模型路由省略显示，完整内容见提示和详情；数值及类型徽章不裁切，多行自然撑高。移动端卡片和详情保持原有字号及触控尺寸。

“事件 → 日志”使用可横向滚动的十列表格：结果时间、账号、模型、触发、执行、结论、预测、匹配度、处置／恢复、通知。首组与汇总对应显示，缺值不推断。执行完成、模型验证通过、取消标记、恢复调度和通知成功分别展示；颜色仅标注对应状态，“未确认降智”不代表已证明模型正常。点击行或账号可打开指定任务详情，键盘 Enter／空格同样有效，关闭后焦点返回。

调度切换通过上游接口写入并读取确认。其他窗口已修改设置时，旧版本保存会被拒绝，刷新后重新编辑。

OpenAI OAuth／Key 的三类明确上游降智错误及慢首字预警作为检测线索，不直接推送 Bark。慢首字规则为最近 24 小时最近 10 条有效文本流式调用中，至少 8 条首字严格超过 10 秒。线索触发该账号有效模型的自动检测，不要求启用定时检测，也不依赖 Bark 开关；不满足账号资格或仍在五分钟冷却内时忽略，不补跑。

自动检测模型在“功能 → 恢复、测活与模型检测”统一配置，默认 `gpt-6-luna`，适用于当前 Companion 连接内的定时、线索、降智复查和恢复模型验证。OpenAI Key 账号可在“定时检测”中单独选择上游模型，或选择“跟随全局”；独立选择也用于该账号的线索检测及降智复查。候选与模型测试共用同一上游目录，手动模型测试默认选中该账号指定的模型，仍可改选。旧历史模型字段不会自动生效。修改模型只影响新任务，已有任务及恢复核对保留创建时的请求模型；额度恢复连接测活继续使用独立配置。

自动检测按任务保存的请求模型判断第 1 组有效指纹：先比较 `astra > sol > luna`，Sol 内部版本切换不降智，其他同等级再比较数字版本；预测为 `gpt-5.6-luna` 仍一律判定降智，`terra`、无后缀及未知模型不参与新增等级比较。命中时保存降智标记并停止调度，重新读取确认后才发送 Bark 重要通知；失败按原重试节奏独立处理。定时、线索、恢复及用卡后的模型验证共用每账号五分钟门限，重启不清空。普通自动检测未命中时继续最多三组，恢复模型验证只执行一组。手动模型测试不自动处置；人工调度或标记变化优先，自动流程不能覆盖。完整规则见 [模型检测](../docs/model-detection.md)。

定时检测支持固定与智能模式。智能模式按最近一小时调用量调整为 5–30 分钟，可设置 5–30 分钟最小下限；没有业务调用时暂停普通检测和降智复查，统计失败暂缓派发并显示原因。已有启用账号升级后使用智能模式、下限 5 分钟，可切回原固定间隔。

已标记账号可继续使用已开启的定时检测。有效复查确认恢复正常并取消标记后发送 Bark，保持当前调度状态；系统因降智关闭的调度仍需手动开启。失败、无效样本或分析不足不清除标记，人工关闭、停用、认证异常及真实额度阻断仍会暂停检测。Codex 窗口满额但有可用点数时不会误暂停；点数未知且没有当前阻断时继续按计划执行，不额外查询额度。

Codex 模型测试固定账号、有效凭据、当前账号上游目录中的文本模型及指纹库版本，绕过账号模型映射。三组样本可选择 1／2／3 并发，失败重试不占用请求槽；只显示指纹推测、路由和进度摘要，不保存题目及原始输出。人工调度可在测试期间操作，不额外触发模型请求。

账号模板支持独立编辑、改名、保存和删除，所有模板规则一致，删除后不会重建。账号列表可勾选多个账号应用指定模板：先查看逐账号差异，再提交整批请求；忙碌账号独立排队，完整结果可在操作待办查看。模板只手动应用，仅更新白名单与模型映射。

自动用卡结合当前有效的上游限流与同窗口 7d 原始额度证据；WS 错误未写入错误表时可使用账号限流状态，消费前再次核对。只有消费确认成功、所选验证通过且调度恢复确认后，才发送一条合并 Bark。

恢复监控每两秒读取已选账号的必要状态。服务端明确恢复时间到点即开始复核，多个必要阻断取最晚时间；仅估算时间保留 60 秒余量。各账号独立核对额度并验证，Bark 投递不会阻塞检查。额度查询预算、验证退避和模型五分钟冷却仍然有效，等待时显示具体原因与下次允许时间。

记录页滚动接近底部时自动加载下一页，失败保留当前记录并就地重试。输出 TPS 与 Sub2API 一致，按输出 Token 除以总耗时显示一位小数；不减去首字时间，缺失首字仍显示“—”。

记录表、移动端卡片和详情统一使用“同步／流式／WebSocket／安全策略／Live／未知”类型徽章，“压缩”独立追加。类型列默认位于模型之后；已有自定义列及空选择保持不变，可从列菜单开启。显示真实压缩标记需要上游 migration 231；旧数据库和旧 Companion 仍可查看普通记录。列表及详情采用紧凑排版，移动端保留原有触控尺寸。

账号状态对当前限流显示琥珀色标签、自动解除倒计时和原因提示；悬浮可查看准确解除时间。仍受限且最近错误后没有成功调用时显示 HTTP 429 入口，点击打开已有错误详情。倒计时到点等待最新状态，不自动判定恢复。

## 构建

需要 Node 24.21.0、pnpm 12.11.2、Rust 1.99.0、Xcode Command Line Tools。

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
pnpm bundle
```

产物位于 `src-tauri/target/aarch64-apple-darwin/release/bundle/`。`pnpm dev` 提供明确标记为“预览”的开发数据，只在开发构建中存在；生产客户端只使用 Rust HTTP 通道。

Android 固定工具链：JDK 21、SDK 36、Build Tools 36.0.0、NDK 28.2.13676358、Gradle 8.14.3、Rust 1.99.0 的 `aarch64-linux-android` 标准库。设好 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME` 后：

```sh
node ../scripts/android_signing.mjs
# 设置上一步输出的 SUB2OPS_ANDROID_SIGNING_PROPERTIES 路径
pnpm bundle:android
python ../scripts/verify_android.py src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
```

签名材料只保存在仓库外的受保护目录；`android_signing.mjs --github` 将它经 stdin 配置为本仓库 CI secrets。不得替换已有签名。Android 仅构建 ARM64，发布前验证签名、最低 API、APK 及全部原生库的 16KB 对齐。

原生仪器测试使用 `node ../scripts/android_fixtures.mjs` 生成仅测试包包含的模拟数据，再构建 `assembleUniversalDebugAndroidTest`。在 ARM64 模拟器中分别运行 `AndroidRuntimeTest#persistAndLifecycle`、覆盖安装同签名 APK 后运行 `#restartUpgradeAndDisconnect`，以及 `#keyboardAndMediaPicker`。带硬件键盘的模拟器需启用软键盘。正式 APK 使用独立的 `releaseSmoke` 测试包，通过系统 UI 验证连接、五页、前后台、重启、覆盖升级和断开，不向正式应用注入测试运行器。

视觉规范见 [DESIGN.md](DESIGN.md)。`desktop-v*` 标签触发构建与发布流程，仅附带 Mac DMG、Android ARM64 APK 和统一 `SHA256SUMS`；不发布 ZIP，历史发布资产保留。

## 云端接口

`/api/desktop/v1` 只接受 `x-api-key` 管理员认证；服务端使用已配置的 Sub2API 内网地址验证权限。读取验证缓存 15 秒，写操作重新验证。账号 DTO 排除 credentials / extra，错误详情按需读取并移除请求正文。不存在桌面免认证模式。

配置通过 `ConfigService` 保存，以 revision 防止覆盖并发修改。部署保持单个 Companion worker，与现有回退控制器共用进程内锁。接口不改变 Sub2API 表结构或源码。

`scripts/desktop_integration.py` 仅可在专用、空账号的隔离数据库运行，要求 `DESKTOP_QA_DISPOSABLE=sub2ops-desktop` 且数据库主机为 `pg`。它验证真实 Sub2API 鉴权、调度写入、分组证据、错误脱敏及并发保存；不得用于生产。

菜单栏阶段诊断保存在应用配置目录的 `panel-diagnostics.log`，最多约 64 KiB，只包含点击、定位、显示、聚焦与隐藏状态，不包含连接或账号资料。

`network-diagnostics.log` 最多约 64 KiB，记录失败路径、HTTP 状态、响应类型、阶段和请求标识，不记录 Key、服务地址、查询参数或响应正文。瞬时失败保留最后快照，在下一刷新周期恢复；云端通过 `X-Request-ID` 关联安全错误日志。
