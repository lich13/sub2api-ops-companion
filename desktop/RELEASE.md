# Sub2Ops 0.1.34

修复仍有 Codex 点数时定时检测被误暂停的问题，支持降智账号定时复查与恢复通知。记录页改为滚动自动加载，输出 TPS 与 Sub2API 保持一致；升级后新增的合资格 OAuth 账号自动归入“测试连接”。

## 新增

- 已标记降智的 OpenAI OAuth／Key 账号可以继续使用已开启的定时检测。恢复正常并核对取消标记成功后，发送“✅ Codex 检测恢复正常，已取消降智标记”Bark 通知。
- 复查只取消降智标记，保持当前调度状态。系统因降智停止调度的账号可以定时复查，但恢复正常后仍需手动开启调度；人工关闭、停用、认证异常及真实额度阻断继续优先。
- 升级后首次发现的 OpenAI OAuth 母账号自动加入恢复监控的“测试连接”分类；停用或关闭调度的账号也可归类，但不会因此自动开启调度或立即查询、测活。

## 改进

- 记录页滚动接近底部时自动读取下一页，首屏不足时继续加载。保留筛选、分页游标、滚动位置、精确消费汇总及新增记录提示。
- 分页失败保留已加载记录，提供原位置重试；后台、离页或打开弹层时暂停自动续读，切换连接与筛选后丢弃旧响应。
- 列表、移动端记录和详情统一显示“输出 TPS”：按 Sub2API 原生规则使用输出 Token 除以总耗时，保留一位小数，不再减去首字时间。缺失首字继续显示“—”；零输出、无效耗时及不适用请求的 TPS 显示“—”。
- 定时复查分别显示取消标记结果与通知状态，通知失败独立重试，不重复模型请求或调度操作。

## 修复

- 移除仅凭界面百分比达到 100% 就暂停自动检测的判断。有可用点数或无限额度时，窗口满额不再阻止检测；点数未知且没有当前阻断时继续按计划执行。
- 兼容原生点数快照的秒级时间、隐藏余额和十进制余额。点数与额度窗口独立判断；过期、畸形或矛盾信息不被当作零余额，重置卡数量不被当作点数。
- 只有有效满额窗口与明确无点数同时成立，或存在当前有效的上游限流、明确额度拒绝时，才因额度暂停。误暂停的已开启任务重新计时，不集中补跑遗漏周期。
- 复查失败、样本无效或分析不足不会清除降智标记；仍符合降智特征时保留标记，不重复停调度或发送处置通知。检测期间的人工修改优先，迟到结果不能覆盖新操作。
- 修复单并发模型测试在首组分析结束前提前派发下一组的竞态；达到提前完成条件后及时停止，网络重试等待仍释放请求槽。
- 失败组重新测试时，第 1 组判定继续使用该组自身的有效样本，不以其他组的汇总结果替代。

## 兼容

- 升级先记录现有 OAuth 账号基线，保留所有已选与未选状态。人工取消、移入模型测试组或同一账号重新出现时，不会被自动重复加入。
- 保留每账号五分钟自动检测门限、现有模型与间隔、指纹库快照、共享凭据互斥及手动测试行为。手动测试仍只展示结果。
- 取消降智标记不自动开启调度，不修改账号模板、模型映射或路由；恢复通知沿用 Bark 总开关、去重及重试机制。
- 保留配置、Keychain、账号数据、额度预算、自动用卡、恢复历史、通知队列及分组草稿；本轮不增加额度查询，不修改 Sub2API 源码、镜像或数据库表。
