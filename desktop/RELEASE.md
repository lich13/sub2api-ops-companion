# Sub2Ops 0.1.30

降智线索先检测、确认后再通知。额度恢复可按账号选择连接测试或模型指纹验证，事件页也能独立查看其他错误。

## 新增

- OAuth 恢复增加“测试连接”和“模型测试”两类账号选择，支持搜索，同一账号只能选择一种方式。模型验证使用账号保存的检测模型，只执行第 1 组有效样本。
- 自动检测确认降智后，先保存标记、停止调度并重新读取确认，再发送“⚠️ Codex 已判定降智，已停止调度”。通知包含账号、触发来源、模型与首组指纹结果；失败会独立重试。
- 每个托管 Key 可选择“OAuth 可用时也启用”。OAuth 确认可用时，勾选的 Key 保持开启；全部不可用时仍按原规则回退，状态未知时不改变调度。

## 改进

- 三类明确上游降智错误和慢首字预警只作为自动模型检测线索，不再直接推送 Bark，也不依赖 Bark 开关。检测未确认降智时忽略线索；失败或样本不足如实展示，不当作正常通过。
- 定时检测、错误和慢首字线索、额度恢复及用卡后的模型验证，统一限制为同一实际账号每五分钟最多开始一轮自动检测。手动模型测试和普通连接测试保持原规则。
- 冷却中的重复线索直接忽略，不积压到期补跑；定时与恢复任务保留必要等待。冷却跨重启保留，失败、取消和超时也计入已开始的轮次。
- 首组有效指纹最高匹配为 `gpt-5.6-luna` 时即确认降智，无额外匹配度门槛。普通自动检测首组未命中时继续最多三组；恢复验证仅使用一组，验证通过后还须复核额度、阻断和暂停归属。
- 自动用卡跟随账号选择的恢复方式。采用模型验证时，先等待检测冷却和执行条件就绪，再消费卡并紧接着验证；验证失败只重试验证，不重复用卡。

## 修复

- 额度区域隐藏已经结束的“已转人工处理”“用卡恢复完成”及旧恢复时间，保留底层任务与消费历史。重置结果未知时仍明确显示“重置待确认”。
- 事件页调整为“降智错误、其他错误、恢复历史”三个标签，分别维护分页和请求状态。其他错误包括普通上游、认证、平台及内部错误，也保留未关联账号和删除实体的记录。
- 有明确本地限流证据的记录从两类错误展示、相关质量判断和用卡证据中排除；真实上游 429、容量错误和上游并发错误继续保留，原始数据库记录不变。
- 检测线索与处置通知分开显示；旧连接、离页或切换分类后的迟到响应不覆盖当前列表和详情。账号操作与分组界面继续保持紧凑布局。

## 兼容

- 升级将原适用 OAuth 账号迁入“测试连接”，模型测试组初始为空；新增账号需明确选择。未选入任何恢复组的账号不自动恢复或用卡。
- 旧客户端继续使用现有接口；不传错误分类时保留原查询口径，旧客户端保存配置不会清空新增选择。
- 升级停止旧降智预警的待发和重试项，不补推历史通知，也不将历史漏报重新触发为检测。其他 Bark 通知保持原规则。
- 保留配置、Keychain、账号模板、分组草稿、指纹库、额度预算、恢复及消费历史。人工调度与标记操作优先，自动处置不套用模板；不修改 Sub2API 源码、镜像或表结构。
