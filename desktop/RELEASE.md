# Sub2Ops 0.1.32

补齐原生重置卡快照的兼容处理，修复补查后仍反复等待冷却的问题，并将账号批量操作按钮调整为相邻排列。

## 新增

- 成功查询重置卡并核对上游保存的快照后，Companion 保存可信卡观测，包括查询时间、数量、到期信息及内容摘要。观测随现有状态原子保存，重启后仍可复用。
- 卡查询和消费回执增加脱敏诊断，记录 HTTP 状态、业务码、重置窗口数和缓存确认结果，便于区分查询失败、缓存未确认与消费结果不确定。

## 改进

- 账号列表的已选数量保持在左侧；“应用模板”和“删除所选”在右侧紧邻排列，间距统一为 8px。保留紧凑字号、危险操作颜色和删除确认。
- 窄屏可将整组按钮换到下一行，两个按钮仍保持相邻；安卓继续保留至少 48dp 的触控高度。

## 修复

- 修复 Sub2API 原生重置卡快照没有 `fetched_at` 时，Ops 无法认定补查结果有效、反复进入补查和查询冷却的问题。旧缓存不会被补上虚构时间，必须经过成功查询与实际快照核对。
- 卡内容、凭据、额度窗口或限流事件变化时，原观测不再直接用于消费；消费前再次核对最新证据，防止旧状态误用卡。
- 状态保存失败、过期卡、缓存未确认和未知消费结果均不会授权重复消费。缺失或畸形的成功回执不会被当作明确用卡成功。
- 并发模型测试保存进度时使用独立快照，避免其他样本接收数据时改写正在保存的诊断信息。

## 兼容

- 保留真实上游 429 和当前账号限流状态两条证据路径；仍要求同窗口原始 7d 用量达到 100%，仅 5h 耗尽不会触发。
- 查询和用卡附带的额度读取继续共用每账号至少一小时、滚动 24 小时最多六次预算；429 不绕过冷却。已确认的卡观测可在冷却结束后复用。
- 用卡明确成功后按原恢复方式验证。只有验证通过且恢复调度已核对，才合并发送一条“✅ OAuth 用卡成功，已恢复调度”Bark；不补推历史通知，通知重试不重复用卡或测活。
- 保留配置、Keychain、账号数据、自动化、预算、消费幂等记录、恢复历史及通知队列。不新增公开业务接口，不修改 Sub2API 源码、镜像或表结构。
