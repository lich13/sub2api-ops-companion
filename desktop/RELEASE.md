# Sub2Ops 0.1.46

本版新增默认关闭的账号保活，修复极端指纹参数导致的 ModelTrace 分析异常，并补齐审计回归。

## 账号保活

- 所有平台和账号类型均可从账号操作中打开“账号保活”，按账号独立设置；升级后默认关闭。
- 开启后每两秒检查原生错误策略造成的临时不可调度，仅在账号允许调度且无其他限制时清除。认证、封禁、额度阈值、账号级限流、降智及正在进行的检测、恢复或人工操作均会阻止派发。
- 使用原生清除接口，该接口同时清除模型级限制；不打开调度、不清除降智标记。数据库确认清除后才计为恢复。
- 同账号恢复至少间隔 60 秒，一小时最多五次；第五次确认后暂停并通过既有 Bark 通道通知。手动重新开启仍保留一小时记录。
- 超时、断线和重启后的未知结果只读核对，不自动重发；面板显示恢复时间、次数及暂停原因，离线和只读时禁止修改。

## 安全与兼容

- 极端但有限的指纹参数导致数值溢出时返回明确错误，避免分析 panic；正常模型排序和已有降智规则保持不变。
- 补齐代理诊断、操作批次引用、异常指纹库及新增保活路由的校验与回归，稳定目录测试的同步等待。
- 直接运行服务时输出脱敏监听范围与端口；保持原有 HOST 默认值、鉴权、接口及数据库结构。
- 保活状态独立持久化，沿用文件锁、原子替换和 0600 权限。原生清除接口没有条件版本参数，无法与其他上游实例形成原子操作。
- 原生安装包移除携带构建机路径的调试信息，并增加 Mac 与 Android 成品路径检查；保留签名和既有下载校验。

## 安装与升级

- 提供 Mac Apple Silicon DMG、签名 Android ARM64 APK 及 SHA256SUMS，不提供 ZIP。
- 升级保留配置、Keychain、业务状态和历史，不补发通知、不重判历史任务、不重放未知请求。
- 回退到 0.1.44 使用当前兼容状态，旧版不读取保活文件；保留该文件以便再次升级时核对未知请求，勿手工清空恢复记录。
