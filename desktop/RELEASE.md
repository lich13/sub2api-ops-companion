# Sub2Ops 0.1.33

统一账号页与分组页的操作菜单，修复原生用卡回执误判和恢复状态续接，并在恢复历史中明确区分自动用卡恢复。

## 新增

- OpenAI 分组账号补齐模型测试、标记／取消降智、定时检测、测试连接、恢复状态、应用模板和删除。各操作沿用账号页的资格判断，恢复状态仅在适用时显示。
- Grok 分组账号增加相同样式的菜单，提供测试连接、适用时的恢复状态和删除，不增加模型指纹测试。
- 恢复历史新增“用卡恢复”，展示账号、验证方式、模型、用卡时间、验证通过时间及恢复时间。仅记录自动用卡完整恢复成功，不将手动用卡、待验证或未知结果列为成功。

## 改进

- 同一时间只展开一个账号菜单；重复点击、点击外部、选择操作、Escape、滚动、切换页面或连接时自动关闭。支持键盘导航与安卓返回键。
- 菜单以独立浮层显示，避免被分组轮廓和滚动容器裁切；菜单关闭后，已提交操作仍继续执行并反馈结果。
- 保留现有紧凑尺寸及移动端触控区。删除账号只使该账号的分组草稿失效，其他草稿继续保留。
- 卡观测失效、预算等待、验证失败与消费待确认分别显示原因，便于定位自动流程停在哪一步。

## 修复

- 修复原生 `code: "reset"`、重置窗口数为正整数时被误判为“结果不确定”的问题；继续兼容原有明确成功格式。
- 区分 `no_credit`、`nothing_to_reset` 和 `already_redeemed`。后者无法可靠关联本轮消费时保持待确认；矛盾、缺失及畸形回执均不授权重复消费。
- 明确消费成功后先保存回执，再处理附带额度缓存。缓存刷新失败不再抹掉已确认的消费结果，额度下降也不会被当作成功回执。
- 兼容本次请求取得的秒级额度时间，避免将有效新快照误判为消费前缓存；旧缓存不会被补上虚构时间。
- 修复恢复调度过程中重启或保存失败后的状态续接：先读取实际调度、控制代次、暂停归属和验证证据，再完成提交，不重复用卡或覆盖人工操作。
- 未消费的旧终止任务在人工重新启用且出现新限流事件后可结束；曾发出消费请求的任务仍须先确认恢复，才能进入下一轮。

## 兼容

- 保留真实上游 429 与 WS 账号限流状态两条证据路径、原始 7d 用量判断及消费前状态复核。
- 查询继续遵守每账号至少一小时间隔、滚动 24 小时最多六次预算；模型验证继续遵守五分钟门限。每轮最多消费一张，验证失败只重试验证，未知消费只核对。
- 消费明确成功、验证通过且调度恢复已核对后，原子保存完成状态、恢复历史及通知意图，发送一条“✅ OAuth 用卡成功，已恢复调度”Bark；通知失败只重试投递，不额外发送普通恢复通知。
- 旧恢复记录和接口字段保持兼容，不根据额度下降或未知回执补造用卡历史，不补推历史通知。
- 保留配置、Keychain、账号数据、额度预算、自动检测、模板、分组草稿及通知队列；不修改 Sub2API 源码、镜像或表结构。
