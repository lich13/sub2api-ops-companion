# Sub2Ops 0.1.84

- 修复缺少来源的旧记录被误当成自动用卡任务、向已删除账号补发通知的问题。删除账号后静默结束当前用卡任务并停止所有待发用卡通知，保留历史和扣卡回执。
- 普通恢复清状态失败后沿用现有重试并重新测活；测活期间刷新限流时间戳不再误判为恢复失败，提前重置检测也能继续使用正常 token 续期前的观测。
- 修复普通请求晚到的额度回包被误判为提前释放、触发无效测活和失败通知的问题。普通恢复在重置点前只接受主动用量查询确认的提前释放，到点恢复和独立提前重置检测保持原流程。
- 精简用卡恢复确认和暂停期间改参检查。保留额度、暂停归属、人工接管及截止时间核对；清状态失败只重试幂等操作，不重复扣卡。启用调度前核对账号仍存在且处于启用状态。
- 手动用量、用卡和持续预约复用已有账号行，单账号响应不再重建全量总览；模型测试首组复用预读数据，等待、重试及后续采样重新读取，保留原采样并发与手动优先。
- 已有审计日志缺少锁文件时也可读取，读取不创建文件或修改权限；每行只解析一次，脱敏在写入时完成，保留已有锁和轮转。
- 删除退役模板、旧恢复计划和旧派发的启动迁移，以及历史补造和多余的跨文件处置兜底；人工修改检测规则后旧处置仍停止，停调度失败仍按原流程重试。
- 支持从 0.1.82、0.1.83 升级，HTTP 响应字段保持兼容。部署失败时保留当前数据修复，不恢复旧快照、不删除扣卡记录。
