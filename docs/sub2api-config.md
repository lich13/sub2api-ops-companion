# Sub2API 配置

“功能 → Sub2API 配置”按分组编辑目标进程实际使用的 `config.yaml`。0.1.60 内置官方 0.2.18、提交 `ac1b8f1271be0d674fa6f074403c1410f30a3a81` 的 529 个配置入口与 16 个内部字段说明。未识别、失效和保留字段明确提示；未知配置值在保存时保留。

页面展示的是文件、进程环境变量与版本默认值的组合，不是运行时内存转储；后台业务设置还可能覆盖部分策略。环境变量优先项只读，包含 `TZ` 和显式空列表的特殊规则。秘密值在客户端内存中按需显示，不存储草稿，不把读取占位符写回文件。完整配置响应禁止缓存。

## 编辑

桌面按分组展示紧凑表单，窄窗口与手机使用分组选择器。默认值和关键范围紧邻输入，完整说明、内部字段及官方源码可展开查看。搜索覆盖所有分组和内部字段；“已修改”汇总当前草稿，点击检查错误会定位到对应输入。大型分组可按路径前缀跳转子节。

未配置的字段可以直接编辑，实际改变后才加入草稿；“写入默认值”显式新增 YAML 项，“恢复默认”删除已有 YAML 项。未配置的列表不会被自动写成空列表。切换分组和功能标签保留草稿，无效 YAML 在修正前禁止检查与应用。

## 应用

检查及应用都重新读取文件和运行进程，校验版本、内容指纹、字段类型、范围与关联条件。应用前展示字段差异；恢复默认删除 YAML 项。写入使用同目录临时文件、原权限与属主、同步落盘和原子替换，重新输出合法 YAML。

宿主机只重启部署绑定的容器，等待新进程与健康恢复，再核对文件和版本。失败恢复应用前文件并重启一次；外部文件或版本变化时停止覆盖。恢复失败保留配置文件旁的 `.yaml.sub2ops-rollback` 副本，处理上次结果后再应用。不会自动升级 Sub2API 或重建数据库、Redis 等容器。

应用由宿主机持有，客户端断线不取消。操作状态仅在内存中保留；发起操作的管理员可以在重启期间及完成后十分钟查询状态，其他接口仍使用上游管理员鉴权。宿主机进程或整机中断时，不自动重放应用；恢复副本可供人工处理。

## 接口

沿用 `/api/desktop/v1` 前缀：

| 接口 | 内容 |
| --- | --- |
| `GET /sub2api-config` | 运行版本、提交、文件指纹、字段目录、配置值和来源 |
| `POST /sub2api-config/validate` | 校验文件及进程指纹和字段变更，返回字段级错误 |
| `POST /sub2api-config/apply` | 同样校验后提交一次应用；返回操作状态 |
| `GET /sub2api-config/operation` | 保存、重启、恢复及最终结果 |

写入请求为 `expected_revision`、`runtime_revision` 与 `changes`；每项只含 `path`、`remove` 和可选 `value`。客户端不能指定容器、文件路径或命令。运行版本没有匹配目录时只读。

## 宿主机安装

`Companion-linux-amd64` CI 成品包含校验过的镜像及 `install-config-host.py`。安装器从该镜像提取同一 Rust 可执行文件，安装 systemd 服务与本机 Compose overlay。通过命令参数绑定已有容器、配置文件、允许的连接 URL 和 Companion UID；参数只保存在宿主机部署配置。

Companion 只挂载宿主机 socket 目录，`SUB2API_CONFIG_SOCKET` 指向接口。socket 使用 `0660`、目录 `0750`，检查 Unix peer UID。Docker 管理与配置文件权限只留给宿主机助手，Companion 不挂载 Docker socket 或 Sub2API 数据目录。未安装助手时原有功能仍可使用，配置页说明不可用原因。

## 更新目录

`python3 scripts/sync_sub2api_config.py --revision <完整提交>` 对照官方固定源码检查字段增删、类型、默认值表达式及来源变化。审核字段说明、默认值、范围、启用条件及环境映射后更新 `server/resources/sub2api-config.json`，运行脚本的 `--version <发行版本> --accept-reviewed` 记录来源指纹，再随 Sub2Ops 发布。`--source-dir` 支持已下载的源码目录；无参数核对当前目录版本。

更新后运行配置契约、宿主机事务测试、前端配置页与接口测试。页面不在后台拉取目录，也不会自动升级目标 Sub2API。
