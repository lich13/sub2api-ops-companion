# 模型检测与通知

OpenAI OAuth 与 Key 的三类明确上游降智错误和慢首字预警只作为模型检测线索，不直接发送 Bark。独立采集任务每两秒读取既有记录；同一账号所有自动模型检测共用五分钟门限，冷却中的重复线索直接忽略。只有按账号规则有效判定降智、标记保存并确认停止调度后，才发送结果通知，失败按 5/30/120/600 秒独立重试。采集水位、标记、冷却与通知状态持久化为权限 `0600` 的独立文件，升级不补发历史通知或补跑历史线索，不修改数据库表。

定时检测仅在账号“允许调度”开启时执行，已标记降智的账号也遵守此规则。关闭调度后保留检测设置，重新开启后，固定模式按保存的间隔重新计时，智能模式根据当前调用档位重新计算到期时间，不补跑错过的次数。有效复查确认恢复正常并取消标记后，发送独立恢复通知，保持当前调度状态。失败或分析不足不会清除标记，人工操作始终优先。Codex 点数与额度窗口独立判断：有可用点数或无限额度时，百分比满额不阻止检测；点数未知且无当前阻断时继续按计划执行，不增加额度查询。

## 固定与智能周期

新启用默认智能模式。最近一小时业务调用按 `usage_logs.account_id` 归属统计，不合并父子账号，不计 Companion 直接发出的检测请求。现有调度循环每分钟批量统计启用智能模式的账号。

| 最近一小时调用次数 | 档位间隔 |
|---|---|
| ≥120 | 5 分钟 |
| 60–119 | 10 分钟 |
| 30–59 | 15 分钟 |
| 10–29 | 20 分钟 |
| 3–9 | 25 分钟 |
| 1–2 | 30 分钟 |
| 0 | 暂停 |

每个账号可设置 5–30 的整数分钟下限，默认 5；实际周期取档位和下限中的较大值。零调用暂停普通周期检测与降智定时复查，统计失败显示原因并暂缓派发，下一轮重试。人工测试及错误线索仍遵守原规则。

周期以最近一次自动检测完成时间为基准；首次启用无历史时以启用时间为基准。重新采样不会顺延截止时间。恢复有调用时重新计算到期时间，不累计补跑；入队及派发前都核对周期、空闲状态和已有冷却。空闲时撤销未派发的周期任务，已经开始的任务正常完成。

设置接口接受可选 `schedule_mode: "fixed" | "smart"`、`min_interval_minutes: 5..30`，省略保持已保存值；设置版本包含这两个字段。响应增加 `effective_interval_minutes`、`recent_request_count`，零调用或统计失败时当前周期为 `null`，统计失败时调用次数也为 `null`。状态、`next_at` 和 `reason` 展示实际等待或暂停原因。

升级时既有已启用账号一次迁移为智能模式、下限 5 分钟；未启用账号保持关闭。原 `interval_minutes` 保留，切回固定模式继续使用。配置和采样写入已有检测状态，无需业务数据库迁移；旧客户端省略新字段时保留设置，旧服务端仅显示固定模式。回退 0.1.53 按旧固定周期运行。

## 模型候选

模型测试、定时检测及恢复模型验证共用当前账号实际请求的凭据与代理，直接读取原始供应商目录。Key 读取对应 `/v1/models`，OAuth 读取带客户端版本的 Codex `/backend-api/codex/models`；子账号核对父账号关系并使用其有效凭据，不合并其他账号或分组白名单。支持 OpenAI 的 `data[].id` 及 Codex 的 `models[].slug`，过滤非文本模型并去重，超过 10,000 条或无效响应返回明确错误，不截断后假称模型缺失。

Sub2API 的管理目录会投影账号映射，并在上游失败时回落到本地默认列表，因此不再作为模型测试的支持证据。“同步上游模型”还会保存能力元数据，浏览候选不会调用该写入接口。普通连接测试继续沿用原管理目录规则。

候选在内存中按账号和连接身份隔离，60 秒内复用；过期时按需刷新，短时故障最多沿用未满五分钟的成功结果。成功空列表会替换旧结果，读取失败不会被当作模型移除。没有可用缓存时返回读取错误，不换模型重试。凭据、代理或相关账号配置改变后重新读取。

## 自动检测模型

“功能 → 恢复、测活与模型检测”中的“自动检测模型”作为当前 Companion 连接内自动检测的默认模型，默认 `gpt-6-luna`。空白保存为默认值，非空值去除首尾空白并校验模型 ID 格式；保存不会遍历账号目录或触发模型请求。额度恢复连接测活仍由 `oauth_recovery_test_model_id` 独立配置。

OpenAI Key 账号可在“定时检测”中从当前账号上游目录单独选择模型，也可选择“跟随全局”。独立选择用于该账号新建的定时、错误、慢首字及降智复查任务；OAuth 检测及恢复模型验证继续使用全局模型。模型测试共用同一候选目录，默认选中已配置的 Key 模型；正在执行的任务保留原模型，人工已改选的模型不会被延迟读回覆盖。

`PUT /api/desktop/v1/accounts/{id}/model-detection` 接受可选 `model_override`：模型 ID 字符串单独指定，`null` 切回全局，省略保持原选择；仅允许 OpenAI Key 账号设置。返回实际 `model_id`、`model_source: "global" | "account"`、`model_override` 和 `global_model_id`。该可选字段保存在现有检测状态中，沿用操作版本校验；旧 `model_id` 字段仍只用于历史及回退，旧客户端提交它会被忽略，不会自动启用历史选择。

启用检测前按同一上游目录校验所选模型，模型消失或目录不可用时保留选择并提示，允许关闭检测，不自动替换模型。目录校验期间有效模型或检测设置变化返回 409，保留草稿后重新读取。全局修改不会覆盖独立选择；已创建任务及原恢复事件的同一次验证使用创建时的模型，不因配置变化重复验证或用卡。

## 自动检测日志

“事件 → 日志”展示所有已创建的自动检测终态任务：正常、降智、失败、取消、中断、待确认、降智复查及恢复验证。手动模型测试、未建立任务的冷却或资格不足原因不进入日志；后者仍在账号检测状态显示。日志不会改变既有错误流、恢复历史及侧栏角标。

任务结束以及旧报告清理前，现有 `model-test-results.json` 保存可选的精简 `result_summary`。摘要只用于展示，不参与降智、恢复或用卡判断。验证通过、已取消降智标记、已恢复调度均须对应实际回执，通知独立显示且用卡合并通知明确标注。升级前已有证据按实际内容展示；已清除的报告显示“历史详情不可用”，不补造结论、不补跑任务或补发通知。

只读 `GET /api/desktop/v1/detection-logs?before=<cursor>&limit=50` 返回 `{ items, next_cursor }`，默认 50、最多 100 条。按结果时间和 `job_id` 倒序；旧任务缺少结束时间时回退开始或排队时间。非法游标为 422，损坏状态为明确错误。详情按指定任务 ID 读取，缺失时保留摘要；界面提供刷新、失败重试、加载更早记录，不提供重测或重发通知。

## 账号判定模式

账号“模型测试”可选择严格或宽松模式；旧账号默认严格模式。手动测试、定时检测、错误触发、降智复查和恢复验证共用此设置。每个新任务保存实际规则，重试沿用原任务规则；修改规则后旧任务仍可展示结果，但自动处置须通过现有代次与人工操作检查。手动测试只展示结论。

严格模式保留各检测源现有规则：ModelTrace 使用下节等级与首组逻辑；LM Detector 保留跨家族证据、最终汇总比较及有效性要求，合并类别或无法明确识别的结果不参与处置。原有提前结束行为保持不变。

宽松模式可编辑“降智模型”，默认 `gpt-5.6-luna`。等待计划采样全部有效完成，不使用首组命中或高置信度提前结束；仅最终汇总预测与目标规范化后精确匹配才判降智。沿用模型 ID 的首尾空白、大小写、供应商前缀和已知 Claude 名称规范化，不按等级或家族推断命中。合并类别、失败、不完整和不可识别的结果不能解除标记或通过恢复验证。目标不在实际检测库的可独立识别模型中时明确报错，不把无法检测当作正常。

`PUT /api/desktop/v1/accounts/{id}/model-detection` 增加可选 `verdict_mode: "strict" | "relaxed"` 与 `degraded_model_id`，响应返回实际值。支持只提交判定字段和现有 `expected_version`，不修改检测开关、间隔和下次执行时间；旧客户端省略字段时保留现值。模式选择即保存，目标回车或失焦保存；保存期间及失败时禁止开始测试，失败保留输入。结果和精简历史摘要携带创建时的规则，不追溯重判历史。

## ModelTrace 严格判定规则

请求模型使用任务保存的 `requested_model`，不使用映射后的转发模型。比较前去除首尾空白并忽略大小写。

1. 预测为空或报告没有有效输出时，不形成有效检测结论，不能据此解除标记。
2. 预测为 `gpt-5.6-luna` 一律判定降智，包括请求本身也是该模型的情况。
3. 其他相同模型不判定降智。仅 `astra > sol > luna` 参与等级比较；`terra`、无后缀、未知等级、非 GPT 或格式不合法的模型不参与新增比较，仍保留上一条强制规则。
4. 等级优先：预测等级更低即降智，更高则不降智。合法 Sol 模型之间的任何版本切换均不降智；其他同等级按版本号的数字段比较，预测版本更低才降智；`6` 等同于 `6.0`，`5.10` 大于 `5.9`。

| 请求 | 指纹预测 | 降智判定 |
|---|---|---|
| `gpt-6.1-sol` | `gpt-6-astra` | 否，等级更高 |
| `gpt-6-astra` | `gpt-6-sol` | 是，等级降低 |
| `gpt-6-sol` | `gpt-6-luna` | 是，等级降低 |
| `gpt-6-luna` | `gpt-5.9-sol` | 否，等级优先于版本 |
| `gpt-6-sol` | `gpt-5.6-sol` | 否，Sol 内部切换 |
| `gpt-6.1-sol` | `gpt-6-sol` | 否，Sol 内部切换 |
| `gpt-6.1-astra` | `gpt-6-astra` | 是，同等级版本降低 |
| `gpt-6-astra` | `gpt-6.0-astra` | 否，版本等价 |
| `gpt-5.10-sol` | `gpt-5.9-sol` | 否，Sol 内部切换 |
| `gpt-5.6-luna` | `gpt-5.6-luna` | 是，强制规则优先 |
| `gpt-6-sol` | `gpt-5.6-terra` / `gpt-5.5` / `claude-sonnet-5` | 不参与新增比较 |

未命中降智规则不等于请求成功；完成状态、有效输出和原有恢复条件仍须满足。指纹库必须包含 `gpt-5.6-luna` 的原有检查继续保留。库中缺少请求模型不会额外阻断检测，仅输出不含原始模型文本的原因诊断。

已保存的历史结论保持原值，不批量解除标记或恢复调度。后续检测、复查和恢复验证使用同一修正规则。

## ModelTrace 严格模式的首组、汇总与复查

自动检测以首组的有效报告即时处置；首组未确认降智时，在本次任务正常完成路径检查有效最终汇总，命中降智则共用账号锁、人工变更检查和处置回执执行标记与关闭调度。回执 basis 为 first_group 或 aggregate，日志、详情和通知显示对应依据。重试第一组时仍独立分析该组，不用汇总冒充首组证据。取消、无效报告及人工干预不会发起新处置；已压缩的历史摘要不用于追溯处置。

取消降智标记需要首组和最终报告均未判定降智，并满足原有的有效输出、完成组、无错误及不可重试等条件。首组正常而汇总降智时不能清除既有标记；本次执行的最终汇总可产生独立注明依据的处置回执。恢复模型验证同样使用任务请求模型；手动模型测试不自动标记或停止调度。

判定调整不改变模型映射、白名单、五分钟冷却、账号互斥及人工控制优先规则。升级不批量重判历史任务，不重放已确认处置、已发送通知或结果未知的请求。
