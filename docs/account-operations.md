# 账号测试与代理检测

单账号和批量代理选择都支持主动“测试连接”和“质量检测”，由 Sub2API 原生接口执行并返回结果。打开弹层不会自动检测，点击检测不会选择或应用代理。

账号页多选操作栏的“测试连接”用于账号本身，最多 1000 个，结果在当前页面展开。OpenAI 使用接受批次时固定的服务端测活模型；Grok 使用原生默认文本模式。供应商白名单或模型目录缺失不阻止提交，也不写入配置；保留原生模型映射并显示实际模型。批次按连接恢复，未派发项可停止，已派发的未知结果不自动重测。

批量测试首次确认整批终态后，成功、失败、取消及待核对结果均按固定截止时间在 3 秒内收起。刷新、失焦、切页不延长截止时间，挂起期间到期则恢复时立即隐藏。提交或读取结果未确认时保留提示及恢复操作。运行中可关闭结果并继续后台执行；关闭后的历史不再自动展开，不提供独立重开按钮。新批次展开新结果，连接切换清除旧计时器；关闭后将结果区内的焦点还给“测试连接”。服务端任务历史和提交恢复能力继续保留。

## 批量恢复状态

账号多选的“恢复状态”只提交可恢复账号，其他项计为无需恢复。沿用现有批量接口 `POST /api/desktop/v1/account-operations/batch`，请求包含 `action: "recover"`、`payload: {}`、`accounts: [{account_id, expected_version}]`、`request_id` 和 `client_id`；每项使用 `operation_versions.recover`，最多 1000 项。返回和查询沿用操作批次结构，`requested` 为空对象，确认结果包含 `verified`，无需写入时包含 `unchanged: true`。

服务端逐项验证账号及恢复字段版本，复用单账号恢复与账号锁；恢复失败或结果未知不重复派发，不附加打开调度、测试或用卡。客户端汇总已恢复、无需恢复、失败和待核对数量。批量恢复要求 0.1.52 服务端，不新增队列或状态文件。

## 按平台优先级排序

优先级页覆盖当前连接全部未删除账号，按实际平台分别以 `(priority ASC, id ASC)` 排列，独立于账号页筛选与显示排序。目标按位置分配 `1..N`，各平台独立且允许使用相同编号。重复、从零或有间隔的编号可直接应用规范化；不可编辑账号不能拖动，若目标会改变其数值则阻止该平台应用。

宽屏最多三栏，窄屏及超过三个平台使用标签。每个平台独立草稿、撤销和放弃，搜索期间禁止编辑与应用。草稿同连接切页保留，重启不保存，切换连接确认放弃；服务端任务不受客户端关闭影响。账号页优先级仍只读，并发和负载因子继续原位编辑。分组及优先级面板的调度开关复用账号页操作与实时快照，不改变草稿。排序执行时显示简短进度和停止入口；结束结果 3 秒消失，刷新不重复显示历史结果。失败、取消或待核对保留重新核对入口，逐项详情不再作为常驻界面。

全部接口位于 `/api/desktop/v1`：

| 接口 | 用途 |
| --- | --- |
| `GET /account-priorities?schema=2` | 完整平台集合、各平台版本及最近任务、全局活跃任务与旧版任务摘要 |
| `POST /account-priority-orders?schema=2` | 提交 `platform`、完整 `ordered_account_ids`、`expected_version`、`request_id`、`client_id` |
| `GET /account-priority-orders/:id?schema=2` | 任务及逐项原值、目标、核验值；`details=0` 只返回摘要 |
| `POST /account-priority-orders/:id/cancel?schema=2` | 停止未派发项；不撤回已完成值 |

非法格式、重复 ID 返回 422，平台／集合／版本／资格冲突返回 409；创建失败不写上游。版本只包含本平台的身份、成员、优先级及编辑资格，名称、用量和其他平台变化不造成冲突。相同请求与内容返回原任务，不同内容拒绝；历史和幂等登记不自动裁剪。

全局同时只运行一个排序任务，与旧单账号优先级写入共用准入闸门。旧待办优先级操作须先完成或取消。每次派发前在账号及父账号锁内核对整个平台，先持久化 `dispatched` 再 PUT；成功回读及用卡暂停归属核对完成后直接持久化 `verified`。未知结果或重启先回读，不自动重复派发。尚未派发的忙碌账号可由后续空闲账号先行，最多一个写入；全部忙时等待既有周期唤醒，进度显示原因。

最终必须核验完整平台集合及全部目标，包括无需修改项；全部匹配且唯一才是 `completed`，唯一性只保证核验时成立。取消、冲突或部分失败保留实际进度，不回滚。重新核对后，集合一致保留原平台目标顺序，集合改变按当前值准备，再次应用使用新版本与请求。

新任务存放 `account-priority-orders-v2.json`。旧 `account-priority-orders.json` 保留原格式；升级停止旧任务后续写入，核对已派发项并收束为待核对，此后只读。只读启动不修改状态，损坏明确报错。无 `schema=2` 的旧列表／任务保持原字段结构，旧全局提交返回 `client_upgrade_required`；新客户端连接旧服务仅可查看。回退 0.1.50 保留新文件和实际编号，不恢复旧快照。
