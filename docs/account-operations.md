# 账号测试与代理检测

单账号和批量代理选择都支持主动“测试连接”和“质量检测”，由 Sub2API 原生接口执行并返回结果。打开弹层不会自动检测，点击检测不会选择或应用代理。

账号页多选操作栏的“测试连接”用于账号本身，最多 1000 个，结果在当前页面展开。OpenAI 使用接受批次时固定的服务端测活模型；Grok 使用原生默认文本模式。供应商白名单或模型目录缺失不阻止提交，也不写入配置；保留原生模型映射并显示实际模型。批次按连接恢复，未派发项可停止，已派发的未知结果不自动重测。

“关闭结果”在提交、执行、完成或失败时均可使用，只隐藏结果区。关闭后通过工具栏的“测活结果”重新打开，后台仍继续执行；关闭状态按连接保存，迟到响应、返回页面或重启不会自行展开。主动发起新批次会展开新结果，“停止未开始”仍是独立操作。

## 全局优先级排序

优先级页覆盖当前 Companion 连接内全部未删除账号，初始按 `(priority ASC, id ASC)` 排列，独立于账号页筛选和本机显示排序。顶部优先级最高，应用目标按位置分配 `0..N-1`。当前编号重复或稀疏时，无需拖动也可应用重编号。不可编辑账号不能拖动，若目标编号会修改它则整次应用被阻止。

搜索和平台筛选仅供查看，存在筛选时禁止重排和应用。草稿支持逐步撤销及放弃，同连接切页保留，重启不保存；更换连接前确认放弃。应用后由服务端持久化执行，关闭客户端不终止任务，返回原连接可继续查看。账号表仍可按优先级排序，并发和负载因子仍原位编辑；旧优先级待办的重新提交入口改为前往优先级页核对，取消旧待办仍可用。

接口位于 `/api/desktop/v1`，要求原有管理员鉴权，写入遵守只读模式。`features.account_priority_ordering` 表示服务支持此能力；旧服务只显示账号及升级提示，不在客户端模拟逐项保存。

| 接口 | 返回或参数 |
| --- | --- |
| `GET /account-priorities` | 完整 `items`、全局 `version`、`active_task` 和 `last_task` 摘要 |
| `POST /account-priority-orders` | `ordered_account_ids`、`expected_version`、`request_id`、`client_id`；返回任务详情 |
| `GET /account-priority-orders/:id` | 任务状态、原值／目标值／核验值、进度、原因及时间 |
| `POST /account-priority-orders/:id/cancel` | 空对象；停止尚未派发项，已派发项继续核对 |

重复 ID 或非法请求为 422；集合、字段版本或资格变化为 409，创建失败不写上游。版本不含名称和用量等无关字段。相同请求 ID 和内容返回原任务，不同内容被拒绝。仅允许一个活动任务，旧未完成优先级操作必须先完成或取消；排序进行时旧单项优先级接口拒绝写入，其余操作保留原有账号锁与父子锁规则。

排序状态保存在 `USAGE_QUERY_STATE_PATH` 同目录的 `account-priority-orders.json`，复用原子替换、文件锁及 `0600` 写入权限，不存凭据，也不向旧操作队列投放子项。缺文件表示尚无任务，损坏会阻止预检并明确报错。任务不自动裁剪。

状态从 `queued` 进入 `running`，启动恢复进入 `checking`。每次写入前核对完整集合、预期优先级与资格，先落盘 `dispatched` 再请求上游。账号忙时等待；已派发请求在断线、超时或重启后仅回读，值不明时进入 `needs_confirmation`，不自动重复派发。成功值补齐用卡暂停归属核对；仅从未派发且全局状态仍一致的项目可继续。

全部账号（含无需修改项）最终回读与目标一致且唯一才成为 `completed`。失败、取消和冲突停止后续写入，保留已完成值，不回滚；保存过程允许短暂重复。`completed` 只保证核验当时唯一，上游后续人工修改可能再次造成重复。重新核对时，集合未变沿用原目标生成新草稿；集合变化按当前值准备。再次应用使用新版本和新请求，已达到目标的项不重写。
